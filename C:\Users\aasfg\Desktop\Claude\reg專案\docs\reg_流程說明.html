內規修訂助理（reg）流程說明

這一份講三件事：整條流程裡人要做什麼、程式做什麼、LLM 做什麼；程式用哪些方法比對；LLM 用什麼方法篩選。適用單本與多本批次。2026-09-18 版，對應 main 分支 f09431e。

一、三個角色的分工

人（法遵／承辦）

  • 把舊版、新版放進資料夾
  • 確認配對清單
  • 在決定表填「要改嗎、改成什麼」
  • 看報告、看提醒
  • 拿定稿去會簽

凡是「要不要改、改成什麼」的決定，只有人能做。程式與 LLM 都不會代填。

程式（Python，不用裝套件）

  • 逐字比對新舊版，做對照表與紅字全文
  • 找連帶條文（四路比對）
  • 十項條文檢查
  • 把決定寫進 Word 開追蹤修訂
  • 終比對驗收三問
  • 每一步留提醒與指紋

結果可重複、可查證。程式只列候選，不做判斷。

LLM（Claude／SPADE）

  • 讀審查包，逐筆判「要不要改」並給分數與理由
  • 逐筆解釋候選為什麼相關、建議怎麼改
  • 複核程式查不到的三件事：條文矛盾、有無逾越母法、修正理由草擬

只讀候選集，不讀全文。每一個主張都要標條號與信心程度。

二、流程一覽

放檔案→ 配對→ 確認清單→ Step 1 比對→ Step 1.6 條文檢查→ Step 2 找連帶→ Step 1.5 LLM 審查→ Step 3 說明理由→ 填決定表→ apply 寫進 Word→ finalize 三問→ Step 4 LLM 複核→ 會簽

單本用 compare → review-pack → review-import → apply → finalize；多本用 配對 → 開始 → batch-review-pack → batch-review-import → batch-apply → batch-finalize，多本會多算「跨本連帶」。

三、逐步說明

Step −1　放檔案與配對

人把舊版放 匯入/舊版/、新草稿放 匯入/新版/（檔名一樣或只差版本字都可以）。

程式配對 用檔名配對、去掉「_v2」「(修訂)」這類版本字，寫出 規章清單.csv；多個候選配不起來的列標「未配對」。

人打開清單確認配對對不對；不對就改清單。

程式開始 檢查清單有沒有過期（檔案換了、多了、少了），上一輪產出自動歸檔到 系統檔案/歷次/，再逐本跑 Step 1。

Step 0　環境檢查

程式檢查 Python 版本、標準函式庫、有沒有 python-docx（只影響 Word 版對照表能不能產）。沒有的東西會印「未檢查」，不會假裝有。

Step 0.5　款目重編與交叉引用（改過款、目才需要）

程式重編款、目的編號；找出全文裡「第五條第二款」「前項」這類引用，判斷改號之後有沒有指錯，可機械改寫的才改寫，指到已刪除的、外部法規的一律只報不改。條號本身不重編（法制慣例保留條號並註記「（刪除）」）。

人看「無法判定」清單逐筆處理。

Step 1　精確比對

程式讀兩版全文（Word 追蹤修訂當「已接受」讀、表格逐格逐段讀），逐段對齊、逐字比對。產出：修正對照表（xlsx＋公文用 docx）、標註版全文（docx，紅字底線刪除線）、條文檢查報告、候選明細、提醒。

異動分五類：新增、刪除、修改算實質異動；編號調整（只有條號動）、僅字形／空白差異（全半形、空格）另外報，不混進同一個數字。條號整批位移會發警告：所有「第X條」引用都要複核。

人看畫面上的「提醒 N 則」，一則都不能跳過：自動編號讀不到、追蹤修訂、新舊放反、文字方塊不比對……

產出在 審閱文件/；連帶決定表在 填寫表單/。

Step 1.2　帶入正式基準（有規格包時）

程式有 diff-cut 產的正式規格包時，每一段對回正式的條文 ID；規格包的引用表用來算「哪些條文引用了這次改的條」（規格包連帶複核）。

Step 1.6　十項條文檢查

程式責任用語變更（應↔得）、數值期間變更、施行日期、條號完整（重複、跳號，含第一條與最後一條）、定義用語、外部法規引用（只列不判）、待補殘留、格式一致、用語混用、附件。每一項三態：通過／未檢查／有問題。

「未檢查」不等於通過。缺舊版、文件沒有「第X條」、條號對不上，這幾項就會是未檢查，人要自己看。

Step 2　找連帶條文（最重要的一步）

程式對每一處異動，用四路比對到全文找「別的地方是不是也寫了同一件事、這次漏改」（方法見第四節），合成連帶決定表。每一列寫來源（哪一路抓到的）、分數、命中的詞或句，讓人查得到為什麼。

多本時再加跨本：A 本改的段拿去 B 本找；B 本的規格包引用到 A 本改的那條也列出來。

Step 1.5　LLM 審查（review-pack → LLM 填表 → review-import）

程式review-pack 把每個候選打包成審查包（md）：異動段的舊文、新文（帶〔刪：〕〔加：〕）、前後文；候選段全文與前後文；要判的事。另附兩張空白表：AI候選判斷.csv、AI異動審查.csv。

LLM逐筆讀審查包，填判斷、分數、理由（規則見第五節）。

程式review-import 驗格式（判斷字、分數範圍、判斷與分數是否對得上、理由有沒有該有的字），驗決定表的候選全文有沒有被手改過；通過才把 AI 三欄寫回決定表、產 LLM審查報告.xlsx。

重跑 review-pack 不會洗掉已填的答案（改寫 .new.csv 並提醒）。

Step 3　LLM 說明理由與建議

LLM對候選逐筆解釋「為什麼可能相關、建議怎麼改」：80 分以上逐筆展開；45～79 分且句首起列表；其餘只講數量。句子層級與文脈那兩路要看句分數與命中的那一句，不看整段分數。語意來源一樣要寫理由。

LLM同時把畫面上的「提醒 N 則」逐則唸出來，以 提醒.txt 為準（畫面會被洗掉）。

填決定表

人用 Excel 開 填寫表單/連帶決定表.csv，逐列填「要改嗎」（改／刪除／不改）與「改成什麼」（改完的整段）。AI 三欄是參考，不是決定。候選全文那一欄不要改（程式靠它核對）。

apply　寫進 Word

程式先核對草稿指紋（草稿中途被換就整支停）、草稿已含追蹤修訂就停；逐列跳到那一段核對原文，只動差異的字，開 Word 追蹤修訂（作者 reg）。產出定稿（帶修訂）、乾淨版（全接受）、套用報告，三份一起換名，不留半套。

改不到的列分兩類：程式做不到（找不到段、原文不符、範本鎖定欄位、段落含巢狀內容）畫面印 [警告] 有 N 列程式沒改到，finalize 會算成未改到；人自己選的（改成什麼跟原文一樣）不擋，只單獨報一行。

人看 [警告] 那幾列，在 Word 裡自己處理。

finalize　終比對與三問

程式拿「原始草稿 → 套用後乾淨版」再比一次，回答三個問題（見第六節）。三個都是零才印「改好」，否則「還有 N 處要看，請勿送出」。多本時會用各本定稿重算跨本連帶，摘要寫「新候選 N（含跨本 M）」。

Step 4　LLM 複核（程式查不到的三件事）

LLM只餵候選集，不餵全文：

  • 條文間邏輯矛盾：同一件事兩處期限不同、一處應一處得、甲條說依乙條辦理但乙條沒有。
  • 是否逾越母法：對責任放寬、數值變更的條文，指出「要查證○○法第○條，因為……」。LLM 沒有查證母法的能力，只出查證清單，不下結論。
  • 修正理由草擬：對照表每一列的「修改依據／理由」草稿。

每一筆標條號、標信心（明確有問題／疑似請人工確認／不確定），判斷不出來就寫不確定。

人確認後產出最終文件、公文初稿，拿去會簽。

四、程式比對的方法

從嚴到寬分四層，一層抓不到才用下一層。每一列候選都標明是哪一路抓到的，可以並列（例如「相似；語意」）。

第 1 層　精確比對（找差異）

做法說明
正規化全半形、空白統一之後才比；顯示用的原文不動
段落對齊Python 內建 difflib（比對兩串東西哪裡一樣、哪裡不一樣）；段落太多時改「帶狀對齊」只比對角線附近
字級標示對到的段再比到字，畫出底線（加）、刪除線（刪）
分類新增／刪除／修改／編號調整／僅字形空白差異

第 2 層　找連帶（都是比字，只是拿的塊不同）

來源拿什麼比什麼門檻補哪個死角
相似改動段整段對全文每一段，比之前先剝條號45 分同一條抄到別章、小改幾個字
關鍵詞只拿「這次改動的那幾個字」去全文找；片段本身也當一個詞，再切前綴後綴；太常見的詞不拿去搜命中即列整段不像、只有改動的概念在別處出現
關鍵詞（文脈）一字之差（五→七）抽不到片段，或片段搜到零筆時，改拿改動處左右各四個字去搜命中即列數字改數字
相似（句）改到的那一句對全文每一句60 分長段落只改一句，整段分數被稀釋
同義詞先用可稽核的詞表把「保險費／應繳金額」換成同一個代表詞再比，表上寫是哪一組詞讓它配上套在上面各路用詞換掉
整條刪除被刪那一條一字不差的孿生條也列出來，摘要標【整條刪除】—別章平行條文也該一起刪

第 3 層　跨本（多本批次）

來源做法
跨本／跨本（句）／跨本（文脈）A 本改的段拿去 B 本，用同一套整段、關鍵詞、句子比
跨本引用B 本規格包的引用表有引用到 A 本改的那條（有條號幾乎一定要看；只寫「依 A 本辦理」的只提醒）

第 4 層　語意（選配，需要 BGE-M3 模型）

前三層都是比字，死角是「講同一件事但用字不一樣」。語意比對用模型把每一句變成一串數字，講同一件事的句子數字接近，不管用字。

做法說明
前處理剝條號、切句、再正規化（跟字面比對同一套）
拿什麼比「改到的那幾句」對全文每一段的每一句與整段，取最高分；「語意依據」欄寫是哪一句對上哪一句
三種分數純語意 0.4（整句意思）＋關鍵詞 0.2（重要的詞有沒有對上）＋逐字 0.4（一個字一個字對）；BGE-M3 官方權重
門檻三分數 0.70；只有純語意時 0.75（真資料校準：孿生條 0.86～0.93、相鄰條 0.72、其餘 0.62 以下）
全排名／粗篩預設全排名（每個單位都算三種，不會漏，1,347 段約 13 分鐘）；設定「語意粗篩」填 N 可先用純語意排一遍只細算前 N 名（200 名約 7 分鐘，真檔上結果相同；40 名會漏「主題不同但講同一規定」的段）
限制只能說「這句跟那句像，0.72 分」，說不出哪個詞對上；SPADE 上跑不了，要在有模型的電腦算完再併回

五、LLM 篩選的方法

審查包裡有什麼

  • 異動段：舊文、新文（帶〔刪：〕〔加：〕）、前後文（有條就整條＋條外前後各一段；無條有款就整款；都沒有就前後各三段，最多前後各 15 段）
  • 候選段：全文與前後文；前後文裡若某段本身就是異動段或候選段，段首會標「※」
  • 要判的事：候選段要不要跟著改；異動段改完跟前後文有沒有矛盾、同條其他項有沒有該一起改卻沒改
  • 單一候選太長時前後文自動縮到前後各三段並註明，不截原文；審查包依字數切檔（預設 60,000 字）

LLM 要填什麼

表判斷（三選一）分數 0–10理由要有的字
AI候選判斷.csv建議修改／需再檢查／不用改建議修改 ≥ 7；需再檢查 4～6；不用改 ≤ 3建議修改要含「改成」；需再檢查要含「請確認」或「請問」
AI異動審查.csv建議修改／需再檢查／沒問題同上同上

判斷與分數對不上、理由缺該有的字、列ID 對不上、缺欄、只有表頭、空檔，review-import 都會退件並講清楚是哪一種錯。

程式怎麼把關 LLM 的輸出

  • 只驗格式與一致性，不改 LLM 的判斷
  • 決定表每一列的候選全文有指紋；被手改過的列不匯入 AI 三欄，列在報告的「原文已修改未匯入」表
  • AI CSV 存成 Big5 或 UTF-16 也讀得進
  • 寫回決定表後產 LLM審查報告.xlsx（總結、候選審查、異動審查；xlsx 寫不出來才退成 csv）

LLM 的共同規則

  • 只讀候選集，不讀全文（50 頁內規 LLM 一定漏看）
  • 每一個主張標條號；標不出來就不講
  • 標信心程度：明確有問題／疑似請人工確認／不確定
  • 不為了給答案編理由；判斷不出來寫「不確定」
  • 只提問題與建議，不改任何條文，不代填「要改嗎」

六、驗收：三個問題與跳過兩類

問怎麼查擋不擋
一、填了改或刪除的列，定稿裡真的改了嗎？「改成什麼」不在乾淨版、或「刪除」的原文還在 → 未改到。apply 跳過的「程式做不到」四類自然落在這裡擋
二、還有留空沒決定的列嗎？「要改嗎」空白 → 未決定（「不改」算已決定）擋
三、定稿冒出初比對沒列過的新候選嗎？終比對候選的指紋不在初比對的已知集合裡；多本時含跨本重算擋
四、填了改但改成什麼等於原文人自己選的不改，單獨報一行不擋
三問都是零才叫「改好」。但「改好」那張紙上會附這一輪的提醒：有幾處標不上去、幾列跳過。三問皆零但有警告時，結論寫「請先看提醒再決定是否送出」。

七、產出檔放在哪

格放什麼誰用
審閱文件修正對照表.xlsx／.docx、標註版全文.docx、條文檢查報告.xlsx、候選明細.xlsx、LLM審查報告.xlsx、套用報告.txt、新版_定稿.docx、乾淨版、終比對候選表.xlsx、終比對驗收報告.txt、各種 提醒.txt；批次根目錄的批次摘要、批次驗收摘要人看
填寫表單連帶決定表.csv、AI候選判斷.csv、AI異動審查.csv人填、程式回頭讀
系統檔案指紋 .json、異動清單.json、語意輸入／語意候選、LLM審查包_*.md、LLM異動清單.md、輸入/（留底原始檔）、歷次/（上一輪歸檔）程式與 LLM

給人看的表只出一種格式：xlsx 優先，寫不出來才退 csv；標註版全文只出 docx；修正對照表另留一份公文格式的 docx。舊版本平鋪的產出資料夾仍讀得到，會提醒「舊排法」，新產出寫進三格。

八、幾條不能忘的原則

  • 候選不是結論。程式和 LLM 只挑出可疑的，改不改由人決定。
  • 未檢查不等於通過。看到「未檢查」要講原因，自己補看。
  • 提醒一則都不能吞。以 提醒.txt 為準，畫面會被洗掉。
  • 草稿中途不要換。指紋對不上整支停；換了就重跑 compare。
  • 舊決定表不要沿用。段次是共用座標，讀檔規則變過就重跑 compare 再把決定搬過去。
  • 定稿一定要在有 Word 的電腦開一次，確認修訂看得到、接受與拒絕都正常。
  • 最終仍需人工複核後才能送出。
