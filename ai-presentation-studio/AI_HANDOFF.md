## 重要注意事項

1. **專案有兩份副本。** 動手前先跑 `git worktree list` 與 `git status`，確認自己站在哪一份、哪一個分支。弄錯會讓工作消失在另一份副本裡。所有開發請在本體 `ai-presentation-studio/` 進行。
2. **不要把 `factory.ts` 的 z 預設值改回 1，也不要把 `element.z || nextZ(...)` 改成 `??`。** 兩者都會讓 BUG-1 復發。`0` 代表「尚未指定層次」。
3. **所有 z-index 一律從 `src/lib/layers.ts` 取。** 不要在元件裡寫死數字，也不要用 `z-[...]` 類別。`layers.test.ts` 會擋住順序被破壞。
4. **不要動 `demo.ts` 既有的 z 值。** 示範簡報的層次是刻意排的。
5. **不要直接刪掉「重疊警告」。** 它有用，只是判斷門檻太寬，要改的是門檻不是功能。
6. **改動 UI 行為時，單元測試之外一定要真的開瀏覽器操作一次。** Session 003 遇過函式測試全過、但根本沒接上的情況。
7. **重疊警告的門檻常數是 `Canvas.tsx` 的 `OVERLAP_COVER_RATIO`（0.6）。** 不要改回「相交就警告」。
8. **右鍵選單的內容由 `src/lib/contextMenu.ts` 的純函式決定。** 要增減項目改那裡並補測試。
9. **確認對話框一律用 `editorStore.confirm()`。** 不要再用 `globalThis.confirm`。
10. **版型的每個元素都必須明確指定 `z`。** 版型元素不經過 `addElementToSlide`，忘了給會全部變成 0。`layouts.test.ts` 會擋。
11. **新增版型時，`Dialogs.tsx` 的 `LayoutPreview` 縮圖要一起加。** 否則新版型會顯示成空白縮圖。
12. **圖片一律轉成 data URL 存進簡報。** 這是維持「單檔可離線開啟」的必要取捨。
13. **驗證即時狀態請看畫面與 DOM，不要看 `localStorage`。** 存檔是延遲寫入的，會落後。
14. **替既有型別新增必填欄位時，務必處理舊存檔沒有該欄位的情況。** Session 006 已經因此出過一次錯：新增 `listStyle` 後，舊存檔全部被誤判成編號清單。判斷式要寫成「等於某些值才算開啟」，不要寫成「不等於某個值就算開啟」。
15. **表格這一版不支援儲存格合併，欄寬一律用比例存。** 不要改成存像素寬。
16. **搜尋取代的範圍只有文字元素與表格儲存格。** 不含投影片標題、備註與 AI Prompt，這是刻意的。
17. **含反斜線跳脫的程式碼不要用 shell heredoc 傳。** 跳脫字元會被吃掉，產生無法編譯的檔案。
18. **所有字型堆疊一律以拉丁字型開頭。** 中文字等寬，跑版來自英文與數字。`fonts.test.ts` 會擋住違規。
19. **只提供 Windows 與 macOS 都有、尺寸一致的拉丁字型**（Arial／Times New Roman／Courier New）。不要加只有單一系統有的字型。
20. **編輯器介面的字型不要跟著改。** 介面字型不會被匯出，改它是多餘的改動。
21. **跨字型、跨系統的版面問題一律實測，不要用直覺推論。** `document.fonts.check()` 連假字型都回報 `true`，不可用來判斷字型是否安裝。
22. **`dist/AI-Presentation-Studio.html` 是編輯器本身的單檔版，不是匯出的簡報。** 匯出的簡報是 `final-presentation.html`。不要搞混。
23. **匯出檔的講者視窗靠主視窗直接寫入子視窗 DOM，不用任何訊息通道。** 不要改成 BroadcastChannel 或 localStorage 同步，那些在 `file://` 上不可靠。
24. **計時器格式有兩份**：`model/presenter.ts` 的 `formatElapsed` 與 `renderHtml.ts` 裡手寫的 `elapsedText`。匯出檔不能 import TypeScript，所以必須這樣。改格式時兩邊都要改。
25. **換頁按鍵對照也有兩份**：`model/presenter.ts` 的 `previewStepFromKey` 與 `renderHtml.ts` 的 `stepFromKey`。同上，兩邊都要改。
26. **「結束連續編輯」統一在 `setEditingText(null)`／`clearSelection()`／`selectSlide()` 三個入口。** 不要改成在每個編輯欄位掛 `onBlur`，表格會變成每移動一格就切一個復原點。
27. **多份簡報用 localStorage，容量約 5～10 MB。** `upsertDeck` 的回傳值一定要處理，存不下時要提示使用者。
28. **`src/lib/layers.ts` 是 z-index 常數，`src/model/layerList.ts` 才是圖層清單。** 名字很像，不要弄混。
29. **讀程式碼推論出來的症狀，一定要實際跑一次確認。** Session 008 與 009 各發生過一次判斷錯誤。
30. **不要對單一檔案跑 prettier。** 這個專案沒有 prettier 設定檔，會產生與其他檔案不一致的引號風格。
31. **「隱藏未完成的 AI 元件」是簡報層級設定，必須同時影響匯出檔。** 備註不受它影響，一律匯出，講者檢視才有東西可看。
32. **搜尋取代永遠不動 AI 元件的 Prompt。** 那是交給外部 AI 的指示，被批次取代會直接改壞產出。
33. **切換投影片比例不會自動重排元素。** 這是刻意的，自動重排更容易把版面弄壞。
34. **表格合併用 `merges` 陣列記錄矩形範圍，`cells` 永遠是完整的二維陣列。** 不要改成在 `cells` 裡挖洞。
35. **增刪列欄時合併會「縮小」而不是「消失」，縮到一格才自動取消。** 這比整個丟掉更貼近使用者意圖。
36. **圖表產生的是 SVG 字串，編輯器與 Renderer 共用 `buildChartSvg`。** 不要為了方便在編輯器另外寫一份 React 版，兩邊會走鐘。
37. **圖表只支援單一數列。** 要多條線請用 AI 元件。
38. **測試失敗時先判斷是實作錯還是測試的假設錯。** Session 011 就是測試的假設比較差。
39. **`axisRange` 是座標軸的唯一來源。** 間距用 1／2／5 × 10ⁿ 自動決定，一定包含 0。不要再寫「單位至少 10」這種寫死規則，對小數是錯的。
40. **圖表的文字寬度一律用 `estimateTextWidth` 估算。** Renderer 沒有 DOM，不能用瀏覽器量測。
41. **標籤放不下的順序：先縮字級（最多六成），再轉 -35 度。** 不要改成截斷文字。
42. **圓餅圖圖例放右側直向排列。** 橫向平均分佈在標籤長時一定重疊。
43. **圖表資料貼上是「取代」不是「附加」。**
44. **不要串接真的 AI API。** 第一版刻意不串。要改必須先問使用者。
45. **不要動 `src/model/sanitize.ts` 的白名單清理。** 那是唯一的 XSS 防線。
46. **完整的「已確定設計決策」清單在 `AI_PROTOCOL.md` 第十二節，以及 Session 003～012 的第 4 節。** 推翻任何一項之前，先讀它。
